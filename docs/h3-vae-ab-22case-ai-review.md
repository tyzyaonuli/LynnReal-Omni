# 22组三路 VAE：AI 视觉评审（2026-09-17）

## 结论

**有条件推荐 Light 作为省显存的通用解码选项，但不推荐无条件替代默认 VAE。** 本次22组中，Light大多保留默认VAE的运动轨迹、主体结构与色调，主要代价是细纹理、毛发、皮肤与小脸边缘变软。高频纹理与精细人像成片仍优先默认VAE。**TAE推荐用于快速预览/粗筛，不推荐承担本批高速运动或小脸细节的最终质量验收。** TAE在低运动近景口齿、手指和中景人物上仍有可用表现，不能说所有场景都失败。

以上是本批视频的AI评审建议，不是人工MOS、统计显著性结论或跨任务通用排名。默认VAE作为比较参照也并非真实图像ground truth。

## 评审方法与证据边界

- 来源是已发布的22组、三路同latent/同音频的CRF16网页预览；逐组读取**视频本身**，重新抽取同一时间点的浏览器解码帧，不复用历史TAE成片。
- 每组三路检查0.25、1.125、2、2.875、3.75、4.875秒，共396个画面；用于检查动作发展、构图与细节变化。固定列A=H3默认、B=Light、C=TAE，本次分析不是盲评实验。
- 对02/06/07/12/14/17/20/22追加2.750–2.958秒、约1/24秒间隔的6帧序列，共144个画面（部分与全片抽样重合），检查局部短时时序。不是每个视频124帧的穷尽检查，不能由此排除全片所有瞬时闪烁/重影。
- 对17/20/22在1.125、2.875、4.875秒追加原生220×220区域的2倍最近邻放大，共27个局部视图；没有超分或补细节。概览每路缩放到672×384；网页编码、缩放和JPEG证据图会影响微小差异，因此不做逐像素质量或细牙数量结论。
- 33张对比图与时间点、URL、列映射存于个人实验记录 `assets/lynnreal-issue2-inputs-20260916/review-22/`（22概览+8短序列+3局部）。已有66路播放检查只证明可播放，不当作质量通过。
- 下文“稳定/接近”均限定于已检查帧；没有观察依据的高速运动、人脸或牙齿维度记为不适用或证据不足。源视频的运动模糊、光照特效和三路共有结构问题不全部归咎于VAE。

## 典型退化与归因

1. **TAE高速时序重构风险：02、06、07。** 相邻帧中有“部分较清楚、部分轮廓涂抹/拉扯”的变化，不能只挑2.833秒附近的一张清楚帧认定质量相当。此处是可观察的输出差异；没有额外实验，不能断言具体是某个temporal层/缓存或实现缺陷。
2. **Light高频细节代价：05浪花、06织物、04岩脊、11皮肤/眉睫。** 大结构通常保留，但纹理被平滑；默认VAE应保留为质量优先选项。
3. **TAE小脸代价：17/20/22。** 放大是读取已有像素，不是提高信息量。T的眼口/镜框更容易合并；D和L也没有恢复出清晰的每颗牙，不把基础生成分辨率不足归因于某一路。
4. **共有缺陷：02不自然车体、04/10速度模糊、21挥手模糊及部分prompt构图偏差。** 由于三路同latent、共有相似缺陷，它们不能作为Light或TAE独有失败证据。正常场景灯光变化（02/05/07）也不是自动等同于解码闪烁。

## 性能是否值得质量折损

对22例的已记录decoder时间求平均，不是重新跑benchmark：

| 指标 | 默认 | Light | TAE |
| --- | ---: | ---: | ---: |
| 平均decoder秒 | 4.5866 | 3.8589 | 0.11544 |
| decoder阶段峰值allocated GiB | 15.9113 | 9.4181 | 1.8644 |

Light比默认少约15.9%的decoder时间（约1.19倍吞吐），阶段allocated峰值低约40.8%；TAE约39.7倍decoder速度，阶段allocated低约88.3%。后者与质量损失并存。

这些不是端到端加速，也不是整条pipeline峰值显存降低：DiT阶段原测峰值约68.3GiB，仍可能决定单卡容量。默认/Light为空间tile解码，TAE为原生顺序时序解码；阶段保留分配和算法不同。结果是本配置实测，而非VAE参数量或独立decoder净显存证明。

- **推荐Light：** 显存预算吃紧、普通人物中景/低速动作、批量预览与对轻度柔化可接受的输出。代价相对温和，主要价值是decoder阶段省显存，其次才是约0.73秒的解码节省。
- **优先默认：** 最终高质量人像、眼口/牙齿/手部细节、小脸身份与镜框保真、织物/细线/浪花/岩纹、需要严格高速结构的成片。不能为了约16%的decoder时间收益默认接受所有细节折损。
- **推荐TAE仅作快速预览/粗筛：** 检查构图、主体是否出现、大动作趋势；尤其适合迭代等待时间重要的流程。不要据TAE预览淘汰仅细节较差的候选，更不要把TAE的高速变形当成默认VAE或采样模型必然失败。

最终建议是保留三档选择：默认用于质量基准和成片，Light作为有条件的省显存方案，TAE用于快速反馈。独立人工连续视频验收仍可补充，但上述22例AI观察和本批推荐已经完成，不能再写成“尚未做任何质量判断”。
